# ApiFuck 0.1.1

**English** | [简体中文](https://github.com/tyuan511/apifuck/blob/v0.1.1/docs/release/0.1.1_zh-CN.md)

This patch reduces validation memory use and repeated MCP argument-validation work compared with v0.1.0.

## Performance

- Preserve the embedded OpenCollection schema's Draft-07 declaration when compiling document validators. This avoids expanding an unnecessary newer-draft meta-schema cache while retaining schema validation.
- Compile and cache each document type's validator on first use. Opening a project that only contains the root collection no longer initializes validators for every request, folder and environment type.
- Cache MCP argument validators per tool. Both the HTTP transport and workspace operation boundary still validate every call; only the compiled schemas are reused.

In a local macOS Apple M4 Release-build allocation test, the core validation path retained approximately **6.1 MiB** after validating only a root collection and **14.6 MiB** after exercising all document types, compared with **82.9 MiB** before this change. These are requested Rust heap allocations in an isolated test, not the desktop application's total idle memory or RSS.

## Reliability and compatibility

- Add regression coverage for cold validation memory, repeated MCP allocations, invalid nested document values and per-tool argument constraints.
- OpenCollection files, local drafts, environments and MCP tool parameters keep their existing formats. No project migration is required.
- Distribution remains a signed and notarized macOS Apple Silicon DMG, Windows x86_64 EXE and Linux x86_64 AppImage, plus checksums.

## Validation and limits

- Local validation covers workspace tests, formatting, Clippy, release-script tests, a desktop Release build and the Release-mode allocation regression test.
- Whole-application idle memory after installation, native rendering and interactive acceptance require separate measurement. The allocation results above are not a guarantee of an equivalent reduction in desktop memory.
- MCP completed-job retention under concurrent workloads is unchanged in this patch.
