# ApiFuck 0.1.1

[English](https://github.com/tyuan511/apifuck/blob/v0.1.1/docs/release/0.1.1.md) | **简体中文**

本补丁相较 v0.1.0 降低了校验过程的内存占用，并减少重复 MCP 参数校验的开销。

## 性能优化

- 编译文档校验器时保留内嵌 OpenCollection Schema 的 Draft-07 声明，避免展开不必要的新版方言元 Schema 缓存，同时保留完整的 Schema 校验。
- 各文档类型的校验器在首次使用时编译并缓存。打开只有根集合的项目时，不再提前初始化所有请求、目录和环境类型的校验器。
- 按工具缓存 MCP 参数校验器。HTTP 传输层和工作区操作入口仍会校验每一次调用，仅复用已编译的 Schema。

在本地 macOS Apple M4 的 Release 构建分配测试中，核心校验路径仅校验根集合后保留约 **6.1 MiB**，覆盖全部文档类型后保留约 **14.6 MiB**；优化前约为 **82.9 MiB**。这些数字是独立测试中的 Rust 堆请求分配量，不是桌面应用的整体空闲内存或 RSS。

## 可靠性与兼容性

- 新增冷启动校验内存、重复 MCP 分配、非法嵌套文档值和各工具参数约束的回归检查。
- OpenCollection 文件、本机草稿、环境和 MCP 工具参数保持现有格式，无需迁移项目。
- 分发格式仍为已签名并公证的 macOS Apple Silicon DMG、Windows x86_64 EXE、Linux x86_64 AppImage，以及校验文件。

## 验证与限制

- 本地验证覆盖工作区测试、格式检查、Clippy、发布脚本测试、桌面 Release 构建和 Release 模式的分配回归测试。
- 安装后的应用整体空闲内存、原生渲染和交互验收仍需单独测量。上述分配结果不保证桌面整体内存同比下降。
- 本补丁未改变 MCP 并发工作负载下的已完成任务保留机制。
